### 3.3 报「TLS / 证书 / certificate」错误？装一次证书

平台用自签证书，客户端默认不信任。**下载证书**：http://119.29.117.27/geek.crt
（或管理员群文件）。先核对 SHA256 指纹与 §4 一致再安装。

- **Windows**：双击 geek.crt → 安装证书 → 存储位置选「当前用户」→「将所有的证书都放入下列存储」→ 浏览选「**受信任的根证书颁发机构**」→ 完成。
  或命令行（无需管理员）：`certutil -user -addstore Root geek.crt`
- **macOS**：双击导入「钥匙串访问」→ 找到证书 `119.29.117.27` → 显示简介 → 信任 →「使用此证书时」改「始终信任」。
  或：`sudo security add-trusted-cert -d -r trustRoot -k /Library/Keychains/System.keychain geek.crt`
- **Linux**：`sudo cp geek.crt /usr/local/share/ca-certificates/geek.crt && sudo update-ca-certificates`
- **iOS / Android**：系统限制，多数第三方客户端不认用户安装的证书 → **建议直接用网页版**，或客户端如有「跳过 TLS 验证 / 允许不安全连接」开关则打开。
- **自带 CA 库的客户端/脚本**（不读系统信任库）：
  - Node：环境变量 `NODE_EXTRA_CA_CERTS=/path/geek.crt`
  - Python requests：`REQUESTS_CA_BUNDLE=/path/geek.crt`（或 `verify="/path/geek.crt"`）
  - 临时调试才可 `verify=False` / `NODE_TLS_REJECT_UNAUTHORIZED=0`，日常不建议。

装完回客户端点「连接测试」应通过。

## 5. 常见报错

| 报错 | 原因 / 处置 |
|---|---|
| TLS validation failed / certificate verify failed | 没装证书，或客户端不读系统信任库 → §3.3 |
| 401 | Key 错 / 已吊销 / 账号被禁用 → 核对密钥页，找管理员 |
| 402 余额不足 | 找管理员充值 |
| 429 请求过于频繁 | 每人 60 次/分钟；同时进行的请求上限 3 个，等上一轮完成 |
| 429 上游模型服务限流 | 全体共享上游额度，约 1 分钟后重试 |
| 模型不可用 | 模型已下架或不在你的 Key 白名单 → 换模型 / 密钥页编辑白名单 |
| 登录反复跳登录页 | 用了 http:// 或局域网 IP 的 http → 必须 https://119.29.117.27 |

## 6. 使用边界

- 余额制：余额 = 管理员累计充值 − 实际花费；网关硬闸兜底，直连客户端也管得住。
- 思考档位、峰时价格（DeepSeek 工作日峰时 ×2）等口径见网页版模型市场说明。
- 平台为单机部署：每周日 05:00 有计划内重启（约 1–2 分钟不可用）。
