# 运维手册（Windows 本机生产部署）

> 更新：2026-11-19 · 适用：Geek AI 网关平台「三件套」本机生产部署
> Linux/Docker 部署见 `deploy/` 与 `scripts/deploy.sh`；本文档覆盖 Windows 免 Docker 方案。

---

## 1. 拓扑与进程

```text
浏览器 ──► Next.js Web :3000（生产 build+start，BFF + 控制台，SQLite 应用库 web/dev.db）
              │  服务端代理（Virtual Key）
              ▼
         LiteLLM 网关 :4000（Python，Postgres 密钥库，用户级预算硬闸）
              │
              ▼
         本地 PostgreSQL 16 :5432（仅 127.0.0.1，二进制 C:/Users/Public/aigw-pgsql）
```

| PM2 应用名 | 进程 | 端口 | 日志 |
|---|---|---|---|
| `aigw-postgres` | `postgres.exe -D …/data`（直接守护本体，不用 pg_ctl） | 5432 | `logs/pm2-postgres.log` |
| `aigw-gateway` | `python -m litellm.proxy.proxy_cli --config ./config.yaml --port 4000` | 4000 | `logs/pm2-gateway.log` |
| `aigw-web` | `node …/next start -p 3000`（NODE_ENV=production） | 3000 | `logs/pm2-web.log` |

- 配置：`deploy/pm2/ecosystem.config.cjs`（`windowsHide: true` 必须保留，见 §6 踩坑）。
- 环境：网关读 `gateway/.env`（LiteLLM 启动时自加载 cwd 下 .env）；Web 读 `web/.env`（Next 自加载）。**改 .env 后必须 `pm2 restart <app> --update-env`**。
- 安全边界：`:4000` 与 `:5432` 只允许内网/本机访问；公网仅暴露 Web（生产建议反代 443→3000，网关不对公网）。

## 2. 日常操作（Git Bash，仓库根目录）

```bash
./scripts/pm2-up.sh            # 首次纳管 / 重建（自动清游离端口占用 → 按序拉起 → 等 :4000 就绪 → pm2 save）
./scripts/pm2-boot-install.sh  # 开机自启（Startup 文件夹 VBS，登录时 pm2 resurrect；无需管理员）
./scripts/pm2-down.sh          # 停止并移除纳管

pm2 status                     # 状态 / 重启次数
pm2 logs aigw-gateway --lines 100
pm2 restart aigw-gateway --update-env
pm2 reset aigw-web             # 清零重启计数
```

- kill 任一进程后 PM2 约 2s 自动拉起（`restart_delay=2000`）；网关冷启动含 prisma migrate，约 30–90s 才就绪。
- 开机自启是**用户登录触发**（无管理员权限方案的限制）。无人值守服务器需配置自动登录，或改用 nssm 注册真服务（需管理员：`nssm install aigw-gateway <python> -m litellm.proxy.proxy_cli …`，AppExit 设 Restart，日志 AppStdout/AppStderr 落盘）。
- Web 代码变更后：`cd web && npm run build && pm2 restart aigw-web --update-env`。**构建前确认没有 `npm run dev` 在跑**（见 §6）。

## 3. 健康检查与验收

```bash
curl -s http://127.0.0.1:4000/health/liveliness        # "I'm alive!"
curl -s http://127.0.0.1:4000/health/readiness         # {"status":"healthy","db":"connected"} ← db 必须 connected
grep "Uvicorn running on http://0.0.0.0:4000" logs/pm2-gateway.log | tail -1   # 确认没静默改绑随机端口
curl -s -o /dev/null -w "%{http_code}" http://localhost:3000/login             # 200

cd web && node scripts/billing-audit.mjs               # 计费审计（含首登改密流程验证，结束恢复初始态）
cd gateway && python -m pytest test_deepseek_peak.py   # 峰时/节假日规则
cd web && node scripts/assert-thinking-depth.mjs       # 思考深度映射契约
node scripts/probe-mimo-billing.mjs                    # MiMo 计费口径诊断（缓存折扣验证）
```

kill 恢复演练（2026-11-19 实测）：
- 网关：`taskkill //PID <网关PID> //F` → **进程 5s 内被 PM2 拉起**，端口仍 4000（日志确认 `Uvicorn running on http://0.0.0.0:4000`）；完整就绪约 33–35s（LiteLLM 冷启动含 imports + prisma migrate，属固有耗时）。
- Web：kill 后 **3s** 恢复 HTTP 200。
- prisma 引擎：kill 引擎进程后补丁轮询同秒检测、**5s** 重建引擎并恢复 `db=connected`（日志见 `prisma_engine_compat.py … gone; triggering reconnect`）。

## 4. 账号安全口径

- `DEFAULT_USER_PASSWORD`：强随机（`web/.env`，勿提交）。新用户/重置账号一律 `mustChangePassword=true`，首登强制改密（中间件拦截业务 API 403，仅放行改密/登出/me）。
- 演示账号 `13800138000`：`node web/scripts/ensure-demo-user.js` 重置为「默认密码 + 首登强制改密」初始态。billing-audit 每次运行自动走一遍改密流程并在结束恢复初始态。
- `ADMIN_TOKEN`：强随机，管理端 API 用 `x-admin-token` 头。轮换：改 `web/.env` → `pm2 restart aigw-web --update-env`；旧 token 立即 401。
- 上游 Key / MASTER_KEY 只在 `gateway/.env`、`web/.env`（gitignore），严禁入库。
- 生产必须 `ALLOW_TEST_HOOKS=false`（测试钩子可写假 Spend）。

## 5. 计费口径（对账依据）

1. **峰时**：DeepSeek 系模型北京时间周一至周五 09–12 / 14–18 空闲价 ×2；周末与法定节假日全天错峰。节假日表双端同步维护：`gateway/deepseek_peak.py` 的 `PUBLIC_HOLIDAYS` 与 `web/src/lib/peak-pricing.ts` 的 `holidayRanges()`。**已同步至 2027**（国办发明电〔2026〕10号，2026-11-05 公布）；调休补班日落在周末仍按错峰（官方「周一至周五」口径）。每年 11 月左右公布次年安排后必须更新双端 + pytest 用例。
2. **缓存折扣**：上游隐式缓存命中（`usage.prompt_tokens_details.cached_tokens`）按缓存价计费（DeepSeek flash 0.02/M、v4-pro 0.15/M；MiMo flash 0.02/M、pro 0.025/M，均与官方价目一致）。旧审计手算忽略 cached_tokens 才出现偏差；审计已改为缓存感知口径，四模型统一 2e-6 严格容差。诊断工具：`web/scripts/probe-mimo-billing.mjs`。
3. **MiMo 截断思考超收（已修）**：历史「±8%」的另一半来源——MiMo 思考被 max_tokens 截断时，上游 `completion_tokens_details.reasoning_tokens` 仍按未截断口径上报（实测 45 > completion_tokens 40），litellm 按 breakdown 计费导致超收 ~10%。`gateway/usage_breakdown_compat.py` 在解析层把 breakdown 之和钳制到 completion_tokens（溢出优先扣 reasoning），计费总量 = 实际生成量。审计 40/40 验证。
4. **预算语义**：余额 = 管理员充值 − 网关用户级 spend。Web 余额门是**软限额**（请求前检查，并发窗口内可能小幅超支，见 §7）；网关 `max_budget`（用户级）是**硬兜底**，直连 :4000 绕过 BFF 也管得住。预算统一在用户级，密钥不单设预算。
5. **中止流式**：客户端中止后本地 SpendEvent 仅在已解析到费用时记账（通常记不到），网关按上游实际 usage 入账。**对账以网关 `/spend/logs` 为准**，本地看板对中止流可能少记；不做异步补差（规模上来后再评估）。
6. **失败不记账**：4xx/5xx 失败请求不写 SpendEvent；限时免费模型 ¥0。

## 6. 踩坑备忘（实测）

| 坑 | 现象 | 处置 |
|---|---|---|
| PM2 弹窗风暴 | Windows 默认可见控制台，关窗发 CTRL_C → 进程退出 → 重启 → 再弹窗 | ecosystem `windowsHide: true`（已设，勿删） |
| 残余进程占端口 | LiteLLM 端口被占时**静默改绑随机端口**；next start EADDRINUSE 崩溃循环 | `netstat -ano \| grep :4000` 找 PID → `taskkill //PID x //T //F`；pm2-up.sh 已自动清理 |
| dev/生产共用 .next | `npm run dev --turbopack` 把开发 chunk 写进 .next，生产 start 加载混合产物 500（Webpack/Turbopack bindings 冲突）；生产构建也会被污染（/_document PageNotFound） | 生产纳管期间**禁止跑 npm run dev**；污染后 `pm2 stop aigw-web && rm -rf web/.next && npm run build && pm2 restart aigw-web` |
| prisma 引擎 Windows 监视器 bug | litellm 1.91.1 用 os.kill(pid,0) 探活，死 PID 触发 SystemError（WinError 6）炸穿轮询与重连 → 引擎死后 DB 永久失联 | `gateway/prisma_engine_compat.py` 补丁（ctypes 探活/终止，随 callbacks 导入）；升级 litellm 修复后可移除 |
| MiMo 截断思考超收 | reasoning_tokens > completion_tokens 时 litellm 按 breakdown 多收 ~10% | `gateway/usage_breakdown_compat.py` 钳制补丁（随 callbacks 导入） |
| 上游共享 Key RPM | 全体用户共用上游额度（DeepSeek 150/min），超限上游 429 | BFF 已翻译友好提示；生产需提升上游档位，见 §7 |
| 孤儿 query-engine | 网关被强杀后引擎子进程残留 | `taskkill //IM query-engine-windows.exe //F` 后重启网关 |
| Git Bash curl 中文 | 内联中文变 GBK | 写 UTF-8 文件 `--data-binary @file`；node 里别用 /c/… 路径 |
| 长跑网关缓存陈旧 | 预算闸失效 | 先 `pm2 restart aigw-gateway` 再排查 |
| Google Fonts 断连 | next/font/google 构建期拉字体失败 → 构建失败 | 已本地化：`web/src/fonts/*.woff2` + next/font/local；更新字体跑 `node web/scripts/fetch-local-fonts.mjs`（走 loli 镜像） |
| 生产模式 HTTP 登不进 | NODE_ENV=production 会话 Cookie 带 Secure，浏览器只在 HTTPS 或本机 localhost 发送；用局域网/公网 IP 的 http://…:3000 登录会反复跳登录页 | 对外必须前置反代终止 HTTPS（443→3000）；仅本机访问用 http://localhost:3000。Compose 的 WEB_BIND 默认 127.0.0.1 |
| LiteLLM API | /key/list 要 return_full_object=true；操作用 sha256 哈希 token；有效期用 duration；IP 白名单是企业版 | 见 `web/src/lib/litellm.ts` |

## 7. 已知限制与规模化路线

- **上游共享 Key 的 RPM 天花板**：全体用户共用一把上游 Key（如 DeepSeek 当前档位 150 次/分钟），上游按 Key 计 RPM，**失败请求也计数但不入 spend/logs**。聚合流量（含测试/重试）超档位时上游直接 429，BFF 已翻译为「上游模型服务限流，请约 1 分钟后重试」（区别于网关预算闸的 429）。窗口约 1 分钟重置。生产多用户必须：① 提升上游账号档位；② 可选在网关侧给用户设 rpm（/user/update）做公平性隔离，防止单用户吃光共享额度。平台自身限流（BFF 60 次/分钟/用户）与上游档位是两层，勿混淆。
- **并发超支窗口（软限额语义）**：Web 余额门在请求前检查，N 个并发请求可同时通过检查，实际超支上限 ≈ 并发数 × 单笔最大费用。预扣冻结方案（ reservation 表 + 分布式锁 + 超时释放）复杂度高，当前单实例内测规模**不做**；网关用户级 `max_budget` 硬兜底 + 管理员充值控制总敞口。规模上来后优先落地预扣冻结。
- **限流进程内存**：登录/聊天限流在 Web 进程内存（`web/src/lib/rate-limit.ts`），多副本不共享。**多实例前必须换 Redis**（或 Postgres）；单实例可缓。
- **金额 Float**：SpendEvent.costCny / 余额为 Float（SQLite REAL），累计巨额流水有精度风险。规模上来后迁**整数微元**（1 元 = 1e6 微元，BigInt 存储），迁移需双写过渡 + 对账脚本。当前金额量级（< 1e6 元）下 Float 误差可忽略，审计容差 2e-6 元覆盖。
- **应用库 SQLite**：单副本限制；多副本前迁 Postgres（见后续工单 WO-P1-04）。
- **spark-x2.6 下架**：上游官方 2026-11-28 下架该模型，到期需从 config.yaml / 模型目录同步下线或替换。

## 8. 备份与恢复

```bash
# 应用库（SQLite）：停 Web 后冷备最稳
pm2 stop aigw-web
cp web/dev.db "backup/dev-$(date +%F).db"
pm2 start aigw-web

# 密钥库（Postgres）
C:/Users/Public/aigw-pgsql/bin/pg_dump.exe -h 127.0.0.1 -U litellm -d litellm -F c -f "backup/litellm-$(date +%F).dump"
# 恢复：pg_restore -h 127.0.0.1 -U litellm -d litellm --clean backup/litellm-<date>.dump
```

上线 checklist 必须勾选「已配置每日备份 + 演练过恢复」。
