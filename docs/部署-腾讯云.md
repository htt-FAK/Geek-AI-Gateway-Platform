# 部署到腾讯云（Linux + Docker Compose）

> 更新：2026-11-19 · 适用：CVM / 轻量应用服务器 · 与本机 Windows PM2 部署（见 [运维手册](运维手册.md)）功能等价
> 仓库已备好国内构建友好的镜像与脚本，按本文顺序执行即可。

---

## 0. 先做三个决定

| 决定 | 选项与建议 |
|---|---|
| **地域与备案** | 国内地域（北京/上海/广州等）+ 域名对外服务 **必须 ICP 备案**（腾讯云备案小程序，约 1–2 周）。没备案/不想备案：选**港澳台/海外地域**（如中国香港、新加坡），域名即用即开，国内访问延迟略高（30–60ms）。上游 DeepSeek/百炼/MiMo 均为国内服务，海外地域回源延迟稍增但可用。 |
| **域名与 HTTPS** | **必须有 HTTPS**：Web 生产模式会话 Cookie 带 `Secure`，`http://公网IP:3000` 登不进去（反复跳登录页）。有域名 → Caddy 自动签 Let's Encrypt（最省事）或腾讯云免费 DV 证书 + Nginx。纯内网/临时演示 → 本机 `http://localhost:3000`（SSH 隧道转发也可）。 |
| **规格** | 最低 **2核4G**（LiteLLM 常驻 ~600MB–1G + Postgres + Next.js + Docker），推荐 **4核8G**、系统盘 60G SSD。带宽：按量 5Mbps 起（文本对话流量小）。OS：**Ubuntu 22.04/24.04 LTS**。轻量服务器可选「Docker CE」应用镜像省安装步骤。 |

安全组（防火墙）原则：**只放行 80/443**（HTTPS 反代）与**受限来源的 22**（SSH，最好限你的 IP）。**不放行 3000/4000/5432**——compose 默认把 Web/网关绑在 127.0.0.1，反代走本机回环。

> **国内服务器拉境外慢/拉不动？两条路：**
> - **推荐 §2A 无 Docker 纯国内源**：apt/pip/npm/node/prisma 全走腾讯云 + npmmirror，不碰 GitHub/Docker Hub/境外，一条脚本装完。
> - Docker 路径（§2–§6）：代码用 scp 上传（§3，别 git clone），镜像走腾讯云 VPC 加速，pip/npm 已在 Dockerfile 里配国内源。

## 1. 拓扑

```text
用户浏览器 ──HTTPS 443──► Caddy/Nginx（宿主机，自动证书）
                              │ 127.0.0.1:3000
                              ▼
                    Docker: web（Next.js 生产，SQLite 卷 web_data）
                              │ Docker 网络 http://litellm:4000
                              ▼
                    Docker: litellm（1.91.1 自建镜像，挂载 config/回调/补丁）
                              │
                              ▼
                    Docker: postgres:16（卷 litellm_pg，仅 127.0.0.1:5432）
```

## 2. 服务器初始化

```bash
# SSH 登录后（Ubuntu）
sudo apt update && sudo apt -y upgrade
sudo apt -y install ca-certificates curl git

# Docker CE（腾讯云镜像源，国内快）
curl -fsSL https://get.docker.com | sudo bash -s docker --mirror Aliyun
sudo systemctl enable --now docker
docker compose version   # 确认 v2

# Docker Hub 镜像加速（腾讯云 VPC 内免流镜像，仅加速 docker.io 官方库镜像：node/python/postgres）
sudo mkdir -p /etc/docker
echo '{"registry-mirrors":["https://mirror.ccs.tencentyun.com"]}' | sudo tee /etc/docker/daemon.json
sudo systemctl restart docker

# 部署目录
sudo mkdir -p /opt/geek-ai-gateway && sudo chown $USER /opt/geek-ai-gateway
```

> 自建 litellm 镜像基于 `python:3.10-slim`（Docker Hub 官方库，走上面加速）；pip 走腾讯云 pypi 镜像、prisma 引擎走 npmmirror，**不依赖 docker.litellm.ai / ghcr.io**（国内常拉不动）。

## 2A. 替代路径：无 Docker 纯国内源（国内服务器推荐）

不用 Docker、不拉任何境外资源。架构与本机 Windows PM2 方案等价：Postgres 走 systemd 原生服务，网关 + Web 走 PM2（Linux 下 `pm2 startup systemd` 开机自启比 Windows 更稳）。

```bash
# 服务器（Ubuntu 22.04 推荐＝Python 3.10 与本机一致；24.04＝3.12 亦可）
# 先按 §3 把源码 scp 上来并解压到 /opt/geek-ai-gateway，然后：
cd /opt/geek-ai-gateway
./scripts/setup-linux.sh
```

脚本一条龙（全部国内源）：
1. apt 装 postgresql / python3-venv / nginx（腾讯云 CVM 的 apt 默认已是腾讯镜像，快）
2. 建 litellm 角色/库（随机密码），systemd 自启
3. Node 20 从 **npmmirror** 二进制装（免 nodejs.org）
4. venv + `litellm[proxy]==1.91.1` 从 **mirrors.tencent.com/pypi**；prisma 引擎从 **npmmirror**
5. 生成 gateway/.env + web/.env（MASTER_KEY/AUTH_SECRET/加密 Key/ADMIN_TOKEN/默认密码全强随机）
6. `npm ci --registry=npmmirror` + prisma generate + next build + migrate
7. PM2 纳管网关/Web + `pm2 startup systemd` 开机自启 + readiness 探针

装完按脚本末尾提示：填上游 Key → HTTPS 反代（§6）→ 安全组 → 验证。

> 与 Docker 路径的差异：备份不用 backup.sh（那是 Docker 版），裸机直接
> `sudo -u postgres pg_dump -U litellm -d litellm -F c -f litellm-$(date +%F).dump` ＋ 停 web 后 `cp web/dev.db`（见 [运维手册 §8](运维手册.md)）。

### 能不能在本地 WSL 构建好再打包上传？

可以，但**不推荐作为首选**：
- 本机 WSL 若是 Ubuntu 26.04（glibc 很新），打包的原生二进制（prisma 引擎/swc 等）到服务器 22.04/24.04 可能因 **glibc 版本差**跑不起来。
- 稳妥的 WSL 方案是在 WSL 里装 Docker（需 sudo）→ `docker compose build` → `docker save` 三个镜像 → 上传 → 服务器 `docker load`（镜像自带运行时，免疫 glibc 差异）。镜像压缩包约 1–2GB。
- 既然服务器用国内源本身就快（§2A），通常没必要绕 WSL。**WSL 适合服务器完全无外网的离线场景**。

## 3. 上传代码

GitHub 直连国内不稳，推荐从本机 scp（Windows Git Bash）：

```bash
# 本机执行（排除依赖/构建产物/敏感文件；.env 单独传）
cd ~/.zcode/workspace/*/Geek-AI-Gateway-Platform
tar --exclude='web/node_modules' --exclude='web/.next' --exclude='web/dev.db*' \
    --exclude='**/__pycache__' --exclude='logs' --exclude='backup' \
    -czf /tmp/geek-src.tgz .
scp /tmp/geek-src.tgz user@<服务器IP>:/opt/geek-ai-gateway/
# 服务器执行
cd /opt/geek-ai-gateway && tar xzf geek-src.tgz && rm geek-src.tgz
```

（有可访问的 Git 远端也可 `git clone`；后续更新用 scp 覆盖或 git pull。）

## 4. 配置密钥

```bash
cd /opt/geek-ai-gateway
./scripts/env-init.sh        # 从 deploy/.env.example 生成 deploy/.env 并随机化全部密钥
vim deploy/.env
```

必填：
- `DEEPSEEK_API_KEY` / `MIMO_API_KEY`：真实上游 Key
- `DASHSCOPE_API_KEY` + `DASHSCOPE_API_BASE`：百炼 Key 与 endpoint（**专属版账号填控制台示例里的 `llm-xxx.maas.aliyuncs.com/compatible-mode/v1`**，公共账号填 `https://dashscope.aliyuncs.com/compatible-mode/v1`；模型 ID 随 endpoint 不同，用 `web/scripts/probe-bailian-endpoints.mjs` 实测）
- `XFYUN_MAAS_API_KEY` / `SILICONFLOW_API_KEY`：可选（不填则对应免费模型不可用）
- `POSTGRES_PASSWORD`：改掉默认 litellm
- `ALLOW_TEST_HOOKS=false`（生产必须）

> **从本机迁移老平台**：直接复用本机 `web/.env` 的 `AUTH_SECRET` / `CREDENTIALS_ENCRYPTION_KEY` / `LITELLM_MASTER_KEY` / `ADMIN_TOKEN`（换掉则老会话失效、加密 Key 解不开），并连同两个数据库一起迁（见 §8）。全新部署则用 env-init 随机值。

## 6. HTTPS 反代（对外访问必做）

**方案 A：Caddy（推荐，自动证书）**

```bash
sudo apt -y install debian-keyring debian-archive-keyring apt-transport-https
curl -1sLf 'https://dl.cloudsmith.io/public/caddy/stable/gpg.key' | sudo gpg --dearmor -o /usr/share/keyrings/caddy-stable-archive-keyring.gpg
curl -1sLf 'https://dl.cloudsmith.io/public/caddy/stable/debian.deb.txt' | sudo tee /etc/apt/sources.list.d/caddy-stable.list
sudo apt update && sudo apt -y install caddy
sudo cp deploy/Caddyfile.example /etc/caddy/Caddyfile
sudo vim /etc/caddy/Caddyfile   # 换成你的域名
sudo systemctl reload caddy
```

域名解析到服务器 IP、安全组放行 80/443 后，Caddy 自动申请并续期证书。访问 `https://你的域名`。

**方案 B：Nginx + 腾讯云免费证书**

腾讯云控制台「SSL 证书」申请免费 DV 证书（1 年），下载 Nginx 版，上传 crt/key：

```nginx
server {
    listen 443 ssl;
    server_name your-domain.com;
    ssl_certificate     /etc/nginx/cert/your-domain.crt;
    ssl_certificate_key /etc/nginx/cert/your-domain.key;
    location / {
        proxy_pass http://127.0.0.1:3000;
        proxy_http_version 1.1;
        proxy_set_header Host $host;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto https;
        proxy_buffering off;          # SSE 流式对话必须关缓冲
        proxy_read_timeout 300s;
    }
}
server { listen 80; server_name your-domain.com; return 301 https://$host$request_uri; }
```

> `proxy_buffering off` 别漏——否则调试台流式输出会卡成一次性吐出。

## 8. 从本机迁移数据（可选）

两个库必须一起迁，且 `CREDENTIALS_ENCRYPTION_KEY` 保持一致（否则加密 Key 解不开）：

```bash
# 本机（Windows Git Bash）：
cd web && node -e "/* 停 PM2 web 后 */" ; pm2 stop aigw-web
cp dev.db /tmp/dev.db
C:/Users/Public/aigw-pgsql/bin/pg_dump.exe -h 127.0.0.1 -U litellm -d litellm -F c -f /tmp/litellm.dump
scp /tmp/dev.db /tmp/litellm.dump user@<服务器IP>:/opt/geek-ai-gateway/
pm2 start aigw-web

# 服务器：
cd /opt/geek-ai-gateway
docker compose -f deploy/docker-compose.yml --env-file deploy/.env stop web
WEB_CID=$(docker compose -f deploy/docker-compose.yml --env-file deploy/.env ps -aq web)
docker cp dev.db "$WEB_CID:/data/dev.db"
docker compose -f deploy/docker-compose.yml --env-file deploy/.env start web
docker compose -f deploy/docker-compose.yml --env-file deploy/.env cp litellm.dump postgres:/tmp/litellm.dump
docker compose -f deploy/docker-compose.yml --env-file deploy/.env exec -T postgres \
  pg_restore -U litellm -d litellm --clean --if-exists /tmp/litellm.dump
docker compose -f deploy/docker-compose.yml --env-file deploy/.env restart litellm
# 迁移后跑一次密钥模型白名单同步（若服务器网关模型列表与本机不同）
cd web && node scripts/sync-key-models.mjs   # 需 web/.env 指向服务器网关（SSH 隧道）
```

## 9. 备份与日常运维

```bash
./scripts/backup.sh                 # pg_dump + SQLite（短暂停 web），滚动保留 14 份
# cron 每日 03:00
crontab -e
0 3 * * * cd /opt/geek-ai-gateway && ./scripts/backup.sh >> backup/cron.log 2>&1
```

- 日志：`docker compose … logs -f <服务>`；容器 `restart: unless-stopped` + healthcheck 自愈，宿主机重启后 Docker 自启拉起全部容器。
- 升级：scp 新代码 → `docker compose … up -d --build`（web 入口自动 `prisma migrate deploy`）→ 复跑审计。
- 监控：腾讯云「云监控」免费基础告警（CPU/内存/磁盘）；可选 UptimeKuma 探 `https://域名/login`。
- 证书：Caddy 自动续期；Nginx 免费证书到期前手动换（腾讯云会邮件提醒）。
- 年度维护：节假日表（每年 11 月）、spark-x2.6 已于 2026-11-28 下架需下线、上游 Key 轮换——同 [运维手册 §9](运维手册.md)。

## 10. 常见问题

| 现象 | 原因 / 处置 |
|---|---|
| `http://公网IP:3000` 反复跳登录页 | 生产 Secure Cookie 只在 HTTPS/localhost 发送 → 必须走 §6 反代 |
| 镜像拉取超时 | Docker Hub 走 `mirror.ccs.tencentyun.com`（仅 VPC 内有效）；litellm 用自建镜像不依赖境外 registry |
| prisma 引擎下载失败 | 构建已设 `PRISMA_ENGINES_MIRROR=npmmirror`；仍失败检查出网 |
| 网关 DB disconnected | `logs litellm` 看 postgres 健康；compose 已设 depends_on healthy；引擎抖动有补丁自愈（Linux 无 Windows os.kill 问题） |
| 百炼模型 401/404 | Key 与 endpoint 不匹配（专属 vs 公共）；模型 ID 随 endpoint 变 → probe-bailian-endpoints.mjs 实测 |
| 备案拦截 80/443 | 国内地域未备案域名会被腾讯云阻断 → 换海外地域或完成备案 |
| 流式输出一次性吐出 | 反代漏了 `proxy_buffering off`（Nginx）；Caddy 默认流式友好 |
| litellm 镜像 prisma generate 报 libatomic.so.1 缺失 | python:3.10-slim 缺 libatomic1，Dockerfile 已补装 |
| web 容器 `exec web-entrypoint.sh: no such file` | 脚本 Windows CRLF 换行，Dockerfile 已 `sed 's/\r$//'` |
| web npm ci 失败（prisma 找不到 schema） | deps 阶段 `--ignore-scripts`，generate 留到 builder；node 已升 22（ai-sdk 要求） |
| 容器内 apt 慢 | Dockerfile 已把 deb.debian.org 换 mirrors.tencent.com |
| OpenCloudOS / 宝塔环境 | 用 Docker 路径（§2–§6），容器内是 Debian 不受宿主系统影响；反代用宝塔 Nginx 或自装 Caddy |
