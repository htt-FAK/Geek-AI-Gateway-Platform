# 修复任务：余额闸门、密钥失败路径、全员用量图表

你在仓库 `Geek-AI-Gateway-Platform` 里改代码。先读下面「现状」和点名的文件，再改。不要根据 `docs/实现交接-手机号登录与网关.md` 里的日/周/月限额来改，那份交接已经过时。改完后按文末「验收」自测，并把交接改成余额模型。

不要顺手做这些：换数据库、Redis 限流、ASR/TTS、皮肤、榜单实时化、把日/周/月限额加回去、给单把 Key 再设一套预算。

## 现状（必须保持）

计费已经是**余额**，不是日/周/月：

- 本地 `User.balanceGrantedCny` 是累计充值。`balanceUnlimited` 为真表示不限额。
- 余额 = 累计充值 − 累计花费。花费优先用网关用户的 `spend`（`fetchUserSpend`），失败再用本地 `SpendEvent` 合计。
- 网关侧用**用户级** `max_budget` 卡住全部 Virtual Key。LiteLLM 的规则是 `spend >= max_budget` 就拒绝。因此 `max_budget` 必须等于 `balanceGrantedCny`（终身上限），不限额则 `max_budget: null`。
- **不要**把 `max_budget` 设成「剩余余额」。网关自己会用累计 spend 去减，再设成剩余会双扣。
- 新用户默认充值 0。控制台 `/api/chat` 在余额 ≤ 0 且非不限额时返回 402「余额不足」。
- 调试台只用 `User.litellmKeyTokenEnc` 这把主 Key。额外 Key 走网关，靠同一个用户级 `max_budget`。
- 模型列表用 `getGatewayModels()`（60 秒缓存，失败回退 `GATEWAY_MODELS`）。
- 编辑密钥的请求已经是 `/api/keys/${token}`（哈希）。不要改回 `keyName`。
- `POST /api/keys/regenerate` 已经会写 `ApiKeyLocal`。

LiteLLM 镜像是 `v1.83.14-stable`。用户更新接口是 `POST /user/update`，字段包含 `user_id`、`max_budget`、`blocked`。不确定时以这个版本的行为为准，不要猜别的字段名。

## 已经修过、不要重做

- 密钥编辑 id 用哈希。
- `GET /api/admin/usage` 会聚合金额、曲线和成员。缺的是**页面仍画空图**。
- 图像消息已能进 `/api/chat` 和调试台。缺的是接口没有限制 URL 形态。

## P0 钱和密钥会错的路径

### 1. 导入用户时网关侧没有预算

`web/src/app/api/admin/users/import/route.ts` 调用 `ensureLitellmUserAndKey(phone)` 时**不传** budget。`web/src/lib/litellm.ts` 里因此不会设置 `max_budget`，也不会 `syncUserBudget`。新 Key 在用户第一次打开控制台之前，直连 `:4000` 是不限额的。

改法：

- 导入时传入 `{ grantedCny: 0, unlimited: false }`。
- `ensureLitellmUserAndKey` 在拿到 Virtual Key 之后必须确认网关用户的 `max_budget` 已经是 0（不限额账号才是 `null`）。同步失败就抛错，让这次导入进 `errors`，不要留下一把没有预算的 Key。
- 只有错误正文明确是数据库没连上（`DB not connected` / `no database`）时才返回 `app_enforced`。404 和其他 5xx 要抛错，禁止再发占位 Key。
- `POST /user/new` 失败时不要空 `catch` 后继续。已存在可以继续；其它错误要抛出去。用户已存在时仍要调用 `syncUserBudget`。

### 2. 充值先改本地，网关同步失败仍返回成功

`web/src/app/api/admin/users/topup/route.ts` 先 `increment` 本地额度并写 `BalanceTopUp`，然后 `syncUserBudget`。`gwSynced === false` 时仍然 200。结果是控制台按新余额放行，直连网关还是旧上限（甚至没有上限）。

改法：同步失败时回滚这次加款和流水，返回 503，正文说明网关预算没写上。不限额开关同样：网关没改成功就不要改本地 `balanceUnlimited`。本地和网关必须同成同败。

### 3. 删掉主 Key 会改用 Master Key

`web/src/app/api/keys/[id]/route.ts` 的 DELETE，在没有下一把本地副本时把 `litellmKeyTokenEnc` 写成 `__app_enforced__:...`。`chatCompletions` 见到这个前缀就用 `LITELLM_MASTER_KEY` 发请求。Master Key 不受该用户的 `max_budget` 约束。

改法：没有可切换的下一把 Key 时，把主 Key 字段清空（`litellmKeyTokenEnc` 和 `litellmKeyId` 设为 `null`）。`/api/chat` 继续对「没有 Key」返回 400。禁止用 Master Key 给终端用户发对话。`app_enforced` 只留给「网关数据库确实不可用」这一条路径，不要在删除成功之后主动写进去。

删除网关 Key 失败时不要删本地副本。现在是先调网关再删本地；保持这个顺序，网关失败就整段失败。

### 4. 重新生成时吊销失败被吃掉

`web/src/app/api/keys/regenerate/route.ts` 和 `web/src/app/api/admin/users/reissue-key/route.ts` 里，`revokeLitellmKey` 失败会 `catch` 后继续签发新 Key。旧 Key 可能还能花同一份余额。

改法：吊销失败且不是「Key 已经不存在」时，不要签发新 Key，返回 502。吊销成功后再签发，并写上 `ApiKeyLocal`（重新生成这条已经写了，重发卡也要写）。

### 5. 禁用账号管不住已经发出的 Key

`web/src/app/api/admin/users/disable/route.ts` 只改 `User.disabled`。Virtual Key 仍能打网关。

改法：禁用时 `POST /user/update`，`blocked: true`。解除禁用时 `blocked: false`，并按当前 `balanceGrantedCny` / `balanceUnlimited` 再同步一次 `max_budget`。网关调用失败则不要改本地 `disabled`，返回 503。

### 6. `/api/chat` 接受任意图片 URL

`web/src/app/api/chat/route.ts` 的 `image_url.url` 只限制长度。调试台只发 `data:image/...;base64`，但接口本身会把 `http://` 转给网关，网关可能去拉取。

改法：只允许 `data:image/png`、`jpeg`、`jpg`、`webp`、`gif` 的 base64。单张解码后不超过 5MB，单请求最多 4 张（现有条数限制保留）。其它 scheme 返回 400。

## P1 记错账、页面和验收脚本

### 7. 流式调用停不掉，费用用正则抠

`web/src/app/api/chat/route.ts`：

- `ReadableStream` 没有 `cancel`。浏览器中止后，上游继续读完，仍写 `SpendEvent`。
- `extractCostFromText` / `extractUsageFromText` 用正则。`usage` 里再嵌套对象时，`[^}]*` 会在第一个 `}` 截断，Token 记少；抠不到费用就记 0。`app_enforced` 的余额只看本地 `SpendEvent`，记 0 等于没扣钱。

改法：

- 把请求的 `AbortSignal` 传给上游 `fetch`。流被取消时停止读取并中止上游。
- 用 SSE 行解析 JSON，取最后一条带 `usage` 的对象，以及 `response_cost` / 响应头 `x-litellm-response-cost`。不要用正则扫整段正文。
- 取消时：已经解析到的费用可以记账；没有费用就不要写一条 0 元把请求数灌进去。

### 8. 花费日志失败被当成「没有花费」

`fetchKeySpendLogs` 和 `fetchAllSpendLogs`（`web/src/lib/litellm.ts`）在非 200 时返回 `[]`。`GET /api/admin/usage` 看到空数组就改用本地 `SpendEvent`，直连网关的花费从全员图上消失，而且看起来像「真的没流量」。另外只请求一次，没有翻页。日期用 `toISOString().slice(0, 10)`，是 UTC 日期，不是上海日期。

改法：

- HTTP 失败或解析失败返回 `null`，不要返回空数组。空数组只表示网关明确没有日志。
- 管理端：`null` 时返回 503，或在 JSON 里标 `source: "error"`，页面显示失败，不要画成 0。
- 按 LiteLLM v1.83 的 `/spend/logs` 分页参数把页拉完，设一个明确上限（例如 50 页）并在截断时让 `source` 能看出来。
- 日期边界按 `Asia/Shanghai` 的日历日计算，保留现在「end 多取一天以免当天被切掉」的意图。

### 9. 全员用量页面不画接口已经返回的曲线

`web/src/app/admin/usage/page.tsx` 的 KPI 和成员表会用接口数据，两张图却写死 `EmptyChartPanel`，总计永远是 ¥0 和 0。接口字段是 `consumptionSeries`、`modelInvocationSeries`，形状与个人看板的 `spendSeries` / `callSeries` 相同（`{ bucket, byModel }`）。

改法：复用 `web/src/components/charts.tsx` 里个人看板用的图，把这两条序列画出来。无点时显示「暂无数据」。`source === "error"` 时显示加载失败，不要显示 0。

### 10. 验收脚本还在测已经删除的周限额

`web/scripts/server-e2e.mjs` 仍断言 `me.json.budget.dailyLimit`、`weeklyUsed`，并注入花费后期待 402「周限额」。当前 `GET /api/me` 返回的是 `balance`，没有 `budget`。`web/scripts/e2e-smoke.js` 已经改成余额，以它的口径为准。

改法：把 server-e2e 的额度段改成：

- 新用户 `balance.grantedCny === 0`，chat 为 402 且文案含「余额不足」。
- 管理员充值后 chat 可以成功（可用现有的 `SKIP_LIVE_LLM` 开关跳过真实模型）。
- `/api/me` 的 `balance` 含 `grantedCny`、`spendCny`、`balanceCny`、`unlimited`。
- 删掉对日/周限额和环境变量 `DAILY_BUDGET_CNY` 的断言。

`web/src/lib/env.ts` 已经不再读日/周/月预算。不要把这些变量加回去。`deploy/docker-compose.yml` 里如果还在往 Web 传 `DAILY_BUDGET_CNY` / `WEEKLY_BUDGET_CNY`，删掉这两行传参。

## 验收

1. 导入一个新手机号，不充值：`/api/chat` 为 402；用他的 Virtual Key 直连网关也被 LiteLLM 拒绝（用户 `max_budget` 为 0，而不是空）。
2. 充值时故意让网关不可达：本地 `balanceGrantedCny` 不变，接口 503。网关恢复后充值成功，直连与控制台都能花，花完都停。
3. 删除账号下最后一把 Key 之后，`/api/chat` 是 400，请求里没有 Master Key。
4. 禁用用户后，他的 Virtual Key 直连被拒绝；解除禁用并同步预算后恢复。
5. `/api/chat` 拒绝 `image_url` 为 `http://` 的请求。
6. `/admin/usage` 在有日志时画出曲线和成员；网关日志接口失败时不是一串 0。
7. `web/scripts/server-e2e.mjs` 对余额断言通过，不再出现 `dailyLimit` / 「周限额」。
8. 更新 `docs/实现交接-手机号登录与网关.md`：写成余额模型、用户级 `max_budget`、上述失败语义。删掉日限额 ¥50、周限额 ¥200、月限额 ¥400 作为现行规则的描述。
